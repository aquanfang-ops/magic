# 模板

数字、门槛、路径一律填**本批报告或该项目执行规范里已有的名字**，不要套用其他项目的检查项。

## 1. 结论

```
## 批次 N 核验结论：通过 / 有条件通过 / 打回

抽查：
- 可追溯点 = <tag 或 hash>；工作区干净/有未提交；报告 FAIL = <n>。
- <报告中的度量 1>：声明值 vs 重算，结论。
- <报告中的度量 2>：…

打回项（若有）：
1. <证据 + 期望>
```

## 2. 下一批提示词

```
批次 N+1：<一句话目标>。
规则不变：构建命令单条、不拼接管道/exit/cd；完成后按该项目习惯打点（commit/tag）；更新批次报告。

A. <主题>
   1. 先量：<要打印的、本项目已有的度量>。
   2. 改法：<最小改动>；禁止 <范围>。
   3. 验证：<本项目已有门槛或本批新立门槛>。
   4. 若 <边界> 则 <默认处置>。

B. <补漏>
   只补本批抽查发现的、或该项目规范已要求但报告没做的项。

C. <债务>
   把跳过/待定变成：真修，或白名单+理由+阻塞说明。

D. <文档>（需要时）
   目标文件：<路径>。只写文档/静态审计，不改 <范围外>。
   列出待用户提供的信息，每项写「缺它阻塞什么」。

E. 收尾
   - 该项目的全量自检 + 期望数字；
   - 删本批中间文件；
   - 输出：可追溯点、每节量前/量后。
```

## 3. 夜间批次

```
优先级：A > B > C > …。每完成一节就打点。
一节连续两次自检不过：回到上一可追溯点，记「未完成」，做下一节。
禁止为赶进度放宽门槛或新增未定义的 PASS 标签。
最终按节报告：完成/未完成、数值前后、打点列表。
```

## 4. 用户观感 → 检查项

```
用户：<原话>
量化：在 <对象> 上度量 <指标>，期望 <值±容差>，依据 <用户/设计/需求原文>。
永久化：写入该项目执行规范，对本类对象生效；本批把数字写进报告。
```

## 5. 作废重做

```
批次 N 的 <节> 作废：<声明> 经验证不成立（<路径/大小/命令输出>）。
这些节按 <正确来源> 重做；其余节保留。
```
